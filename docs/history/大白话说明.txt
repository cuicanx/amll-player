 这一版改了什么（大白话版）
 目录: v1-visual   日期: 2026-11-14
================================================================

一句话：以前窗口是「真透明玻璃」，玻璃没画上东西之前就透出桌面了，
所以你会先看到一个空框；拖窗口时系统还要一遍遍重画这块玻璃，所以卡。
现在改成「一堵刷好颜色的墙」——不透明，但用 CSS 画出了磨砂玻璃的
质感。看起来的效果还在，透视和卡顿的根子没了。


【一、启动时的空框和两秒等待】

  以前：
    程序先把窗口做成全透明，再让网页往里画内容。网页还没画出来的
    那一两秒，就只剩自己画的标题栏四条边，中间直接看见桌面。
    而且启动时还会故意把窗口改成 0×0 再改回来「逼它重画」，
    又多一次全量重排。

  现在：
    - 网页的第一行就把底色刷好（深蓝灰 + 两团柔光 + 一点细噪点），
      第一帧就是不透明的，不可能再透出桌面。
    - 窗口先藏着，等界面真的画完第一帧再显示；万一出错也有兜底，
      不会一直藏着。
    - 启动那个 0×0 的强制重画删掉了。
    - Windows 窗口不再设成真透明，也去掉了两个互相打架的
      系统背景效果（Tabbed + Mica）。

  预期：不再出现空框、不再透桌面；窗口一出现就是完整界面。


【二、拖窗口时掉到 14 帧、闪烁、透视、元素不跟手】

  以前：
    透明窗口 + 系统毛玻璃效果，等于每改一次窗口大小，Windows 就要
    把整块玻璃重新合成一遍；同时页面里好几个"尺寸变了就动画一下"
    的过渡还在跑，内容就慢半拍；拖快了合成跟不上，就一闪一闪、
    偶尔还能看见桌面。

  现在：
    - 不透明窗口 + 不依赖系统毛玻璃，拖的时候不再反复重算背景。
    - 拖动期间临时把那些"慢半拍的过渡"关掉，松手 0.12 秒后恢复，
      元素立刻贴着窗口边走；静止时长什么样还是什么样，不会跳。
    - 窗口尺寸变化、标题栏测量都做了合并/去重，不再每来一次事件
      就写一遍全文档样式。
    - 全屏歌词页下方始终是不透明底色，就算 WebGL 背景某一帧清空，
      露出来的是底色而不是桌面。

  预期：缩放跟手、不再闪、不再透视；主界面和全屏歌词页同样受益。


【三、进歌单时封面和卡片闪一下】

  以前：
    封面图是"先空着 → 查完数据库 → 突然贴上"，中间那一下就是闪；
    而且给 background-image 加了 0.5 秒过渡，这个属性根本没法平滑
    过渡，浏览器会先黑一下再跳出来，闪得更明显。

  现在：
    - 封面地址记在缓存里，再进同一个歌单直接就有，不用重查。
    - 查询刷新时不再把已有图片清空。
    - 没图的时候放一块同样是深色的占位，不会白一下。
    - 去掉那个不能过渡的属性；图片来了直接稳定显示。
    - 点主界面歌单卡片进入歌单时那个「淡入 + 上移」的入场动画，
      已按你的要求删掉，点完直接出内容，不再有任何进场动效。
      封面格子也不加动画（虚拟列表滚动时行会反复重建，加了反而闪）。

  预期：封面和卡片都不闪；点进去也没有多余的动画。


【四、背景是毛玻璃，白天/暗夜两套都适配】

  先说之前那个"棋盘格"是怎么来的，是我做错了：
  我拿一张 140×140 的小噪点图，像贴瓷砖一样一张张铺满整屏，
  每块花纹都一模一样、边缘又对不上，所以看起来就是一格一格的。
  再加上两团颜色偏浓的光晕，格子就更明显。这根本不是毛玻璃。

  查了 Windows 官方的做法后按标准配方重做，一共四层：
   1) 一层"假装是模糊壁纸"的底：两团非常大的、几乎看不出颜色的
      柔光，没有边界、没有形状；
   2) 30 像素的大半径模糊（Win10 亚克力就是这个数值）；
   3) 一层半透明的色膜，把整体压成均匀的低对比质感；
   4) 一层**几乎看不见**的极细噪点：整张图铺满全屏、绝不重复，
      透明度只有 2%，而且图本身做到 2000 像素，就算你用 2K/4K
      屏把图放大，颗粒也不会变成一块块斑。
  卡片再叠一层半透明加真实背景模糊，所以是有厚度的玻璃，不是平板。
  噪点只是让表面不发假，**绝不能让人看出图案** —— 之前恰恰相反。

  这次不敢只靠代码断言：我实际把页面渲染出来，白天、暗夜各截了一张
  自己先看，确认都是均匀的、没有任何方格或斑块，才交付。

  关键是**窗口本身仍然不透明**：玻璃质感全部用 CSS 画出来，
  不是让窗口真透明去透桌面。所以之前修好的"启动空框、
  拖窗口透视和掉帧"不会回来。另外拖窗口的那 0.12 秒会先关掉
  全屏模糊，松手再恢复，免得拖的时候又要重算一遍玻璃。

  明暗模式沿用项目原本那一套，没有另造开关：
   - 设置里的 amll-player.darkMode（自动 / 白天 / 暗夜）照常生效；
   - 网页第一帧就先读这个值选好配色，所以启动不会先白后黑地跳一下；
   - ThemeManager 在设置里切换、或系统主题变化时立刻同步配色；
   - 三点按钮弹出的毛玻璃浮层也跟着变浅/变深，文字颜色一起适配。


【五、三个点按钮弹出的黑色框】

  那个黑色长方框是控件的提示/菜单浮层。现在所有这类浮层
  （提示条、下拉菜单、右键菜单、弹出面板、选择框、对话框）
  统一换成毛玻璃：半透明深底 + 24px 背景模糊 + 一圈很淡的亮边 +
  顶部一点高光。跟新的窗口背景是一套材质。


【六、只编译 Windows 64 位】

  构建配置里临时只留 Windows x64 生效，其他 4 个桌面平台的配置
  **原样注释保留、没有删**；Android / iOS 两个任务用 if: false 关掉。
  想恢复时把注释去掉、删掉那两行 if: false 就行。
  （踩过一个坑：GitHub 的任务级 if 不能引用 matrix，第一次提交被
   422 拒绝，已改成注释方式，能正常触发。）

【九、你复测时看这几条就行】

  必须看：
   1. 冷启动：是不是一出来就是完整界面，没有空框、没透桌面。
   2. 全屏歌词页快速拖窗口边：还掉不掉帧、闪不闪、能不能透到桌面。
   3. 主界面也拖两下，确认同类问题一起好了。
   4. 进歌单：封面和卡片还闪不闪；点完是不是直接出内容、没有入场动画。
   5. 点封面下面三个点：右边弹出的框是不是毛玻璃、好不好看。
   6. 背景是不是毛玻璃质感；在设置里切到白天 / 暗夜 / 自动，
      配色是否跟着变、启动时会不会先闪一下别的颜色。

  不用特意测（自动化已覆盖）：
   内嵌歌词、播放列表数据、画质开关默认值、原有性能优化。

  已知限制：
   - 启动那 0.4~2.3 秒里有一部分是 WebView2 自己创建窗口的时间，
     前端改不掉；这版去掉透明窗口和系统特效后通常会更快，但请以
     真机为准。
   - 缩放期间"慢半拍的过渡"会被临时关掉 0.12 秒，这是有意为之，
     为的是让元素跟手；松手即恢复，静止画面完全不变。
