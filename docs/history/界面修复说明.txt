 界面与交互修复说明（保留毛玻璃，不回调成旧样式）

一、毛玻璃：只调"透多少、压多深"，不换材质
----------------------------------------------------------------
  浮动层（菜单/提示/右键/对话框）
    背景不透明度   浅色 0.72 → 0.92 ；暗夜 0.76 → 0.94
    阴影           0 15px 30px …18%  →  0 10px 24px …14%
                   暗夜 0 10px 30px 50% → 0 10px 26px 45%
    顶部高光       0.55 → 0.45（减少发白，文字更稳）

  卡片/面板
    浅色 0.62 → 0.82 ；暗夜 0.62 → 0.86

  菜单项悬浮（你说的"几乎不可读"）
    原因：Radix 会用 --accent-contrast 给悬浮项换对比色文字，
    我们的浮层原本是半透明浅底，换出来接近白色；再叠一层黑色
    悬浮底色，就变成"黑底白字挤在一起"。
    修法：把 --accent-contrast / --gray-contrast 固定为浮层文字色，
    并强制 [data-highlighted] 及其所有子元素继承该颜色；
    悬浮底色改为一层很薄的中性色（浅色 7% 深、暗夜 12% 白）。
    效果：悬浮时只是"底色略深"，文字颜色不变。

  扩展程序页顶部两条提示
    它们被当成了浮动面板，套用 0 15px 30px 的大投影，看起来像
    浮在空中的卡片。现在单独用 0 1px 2px 发丝阴影，贴着页面。

  当前播放列表浮窗被设置页遮挡
    设置页外层是 position:fixed + z-index:1000 的全屏层，把播放
    列表浮窗压住了。浮窗改为 position:fixed + z-index:1100。

  右键菜单（歌词页）与播放列表同样受益于上述统一变量，
  透明度与阴影一起下降，无需单独改。


二、F11 全屏：黑边 + 生硬
----------------------------------------------------------------
  黑边的真正原因
    窗口处于"最大化"时直接 setFullscreen(true)，Windows 的
    最大化边框仍按工作区（屏幕高度 - 任务栏）计算，切到全屏后
    客户区没有重算，底部就留下一条任务栏高度的黑边。
    普通窗口（未最大化）没有这个预留，所以你说"非全屏时正常"。

  修法
    1) 进入全屏前先判断是否最大化；是则先 unmaximize，等两帧
       让窗口尺寸落定，再 setFullscreen(true)。
    2) 退出全屏时把原来的最大化状态恢复回去，窗口不会莫名变小。
    3) 切换前后加 140ms 的全屏黑色遮罩淡入/淡出（纯 opacity，
       合成器层，不占帧时间），把"硬切"变成"暗场切换"。

  说明：Windows 原生全屏切换没有系统动画，只能这样用遮罩过渡；
  这不是动画时长的问题，而是把跳变藏起来。


三、任务栏歌词：开启/重启时闪一下
----------------------------------------------------------------
  原因：窗口创建时就是 visible(true)，但它是在创建之后才被嵌入
  任务栏。中间那一小段时间，它会以默认位置/尺寸的透明窗口出现
  一瞬，然后才被塞进任务栏 —— 就是你看到的"闪一下"。

  修法
    1) 窗口创建时 visible(false)，不再抢跑。
    2) 前端在首帧渲染完成后调用 show()（双 rAF + 300ms 兜底）。
    3) Rust 侧再兜一层：1.5 秒后若仍不可见就直接 show，防止
       页面脚本异常导致控件永远不出现。


四、贡献者列表加载慢
----------------------------------------------------------------
  原来：先请求直链，失败或超时才换镜像，最坏要等第一个源超时。
  现在：镜像与直链 **同时发出**，谁先返回就用谁（Promise.any），
  并立即取消较慢的那条请求。
  这本身就是"实时测速选快的"，总耗时等于两者中较快的一个。
  上游更新检测也改成同样的竞速方式。


五、README 与仓库可发现性
----------------------------------------------------------------
  README
    README.md 现在是简体中文（GitHub 默认展示的就是它），
    英文移到 README-EN.md，两者顶部互链；

  仓库可发现性（这里必须如实说明）
    已做：
      - 清空仓库 description
      - 清空 homepage（原先指向上游 Pages）
      - topics 本来为空
    做不到：
      - GitHub **没有**"公开但不可搜索、仅直链可访问"的选项。
        官方社区 2026 年 3 月的同类需求仍在讨论中，官方回复是
        "private 仓库 + 协作者"是推荐做法。
      - 你这个仓库是 **fork**，Settings → Danger Zone 里
        「Change repository visibility」显示
        "For security reasons, you cannot change the visibility of a fork"，
        同时也没有「Hide from profile」选项。
    
    因此目前的结果是：公开、直链可访问、描述已清空（降低站内
    搜索权重），但**无法阻止它被 GitHub 搜索或搜索引擎收录**。

    如果一定要"搜不到"，只有两条路，都需要你决定（都不可逆）：
      A. Settings → Danger Zone → Leave fork network，脱离 fork 关系
         变成独立仓库。之后可能解锁可见性/隐藏选项，但这一步
         GitHub 明确标注不可撤销，且会失去"forked from"标识。
      B. 改成 Private。彻底搜不到，但匿名直链打不开，**自动更新
         与 release 下载会一起失效**（更新器是匿名拉取的）。
