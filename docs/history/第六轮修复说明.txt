本轮修复说明（右键菜单定位 / 全屏 / 更新校验 / 卡片 / 勾选 / 歌词滚动）
================================================

一、右键菜单第二次仍在原点位 —— 这次找到真根因了
------------------------------------------------
前三次我都判断成 CSS 问题（先怀疑过渡动画里的 transform，又改 z-index、
又换定位层），所以一直没修好。**位置根本不是 CSS 决定的。**

Radix 的 `ContextMenu` 在菜单已经打开时，你在别处再右键，它内部 `open`
状态**没有变化**（true → true），于是：

  · 内容组件不重新渲染；
  · 锚点仍然是第一次保存的 pointer 坐标；
  · 结果：菜单一直停在第一个点位。

修法（不再依赖 Radix 的 ContextMenu 定位）：
  · 页面自己在 `onContextMenu` 里取 `event.clientX / clientY` 存进 state；
  · 菜单改成 `DropdownMenu`，挂在一个 0×0 的 fixed 锚点元素上，锚点坐标就是
    这次右键的位置；
  · `DropdownMenu.Root` 用坐标做 `key`，**每个点位都是一个全新的弹出层**，
    不存在"沿用旧锚点"的可能；
  · `onOpenChange(false)` → 清空坐标，下一次右键重新测量。
  · 附带收益：菜单只在打开期间挂载，全屏项的状态每次打开都会同步一次。

二、全屏：进不去 / 退不出 / 退完不能拖动
------------------------------------------------
根因是两个坑叠在一起：

1. **`isFullscreen()` 在 Windows 上会滞后。** 第二次按 F11 时它仍返回 false，
   于是又走"进入"分支；而进入分支里 `unmaximize()` 与 `setFullscreen(true)`
   是 `Promise.all` 并发的——unmaximize 后到会把全屏样式清掉，结果窗口回到
   普通大小但标题栏已经被隐藏，**既不是全屏也不能拖动**。
2. **右键菜单"永远显示进入全屏"** 也是同一个滞后值：每次打开都 `sync` 一次，
   用 false 覆盖了正确状态。

修法：
  · 模块自持权威 `state`：切换时写入，切换后 900ms 内忽略滞后的原生读数；
  · 判断"是否真全屏"改用**几何**：窗口是否覆盖整个显示器（容差 8px；最大化
    会差一个任务栏高度，仍能区分），不再依赖那个缓存标志；
  · 窗口调用一律**严格串行**：进入是先 `unmaximize` 再 `setFullscreen(true)`，
    退出是先 `setFullscreen(false)` 再 `maximize`，不再并发；
  · 进入后轮询确认 700ms，**没真正全屏就回滚标题栏**，绝不会再留下"没有
    标题栏又没全屏"的死窗口；
  · F11 忽略 `event.repeat`：按住时 keydown 每 ~30ms 重复一次，晚到的重复会在
    切换刚完成后立刻切回去，表现就是"有时候按了没反应"。

三、更新偶发签名校验失败
------------------------------------------------
触发条件（三个都不确定，所以表现为"偶发"）：
  · 透明代理缓存了**同名旧文件**（同一 commit 重跑会生成同名安装包）；
  · 传输被截断；
  · 代理返回 200 的错误页（HTML）。
这三种都会让下载到的字节与清单里的签名不匹配。

修法：Rust 侧对签名/校验/解码/截断/网络类错误**自动换另一条源重试一次**
（镜像 ↔ 官方），验证发生在安装之前，坏包永远不会被安装。前端收到
`updater://retrying` 会把进度清零并显示"正在连接更新源…"，`updater://started`
每轮重置进度，不会出现进度条回跳。

四、其他共建者卡片
------------------------------------------------
  · 略微缩小：`Card size="1"`、栅格 17rem、maxWidth 24rem；
  · 头像改回**正圆**：不再用 Radix 的 Avatar（它在本项目的主题令牌下渲染成
    圆角方块），改为自绘 22px 的 `border-radius: 50%` 图片，加载失败时回退
    首字母圆块，两种状态形状一致。

五、右键菜单勾选符号移到右侧
------------------------------------------------
Radix 把勾选标记放在**左侧绝对定位的槽位**里，并给整份菜单加大左内边距；
未勾选时那个空槽就变成了左边多出来的缩进。

现在：隐藏内置指示器，行内边距改回与其它项相同的 9px，勾选标记用
`margin-left: auto` 贴右边。未勾选时左侧没有任何缩进，所有行左缘对齐。

六、歌词滚动
------------------------------------------------
  · **滚动时不再隐藏鼠标**：滚轮（和触摸）也算指针活动，只要在滚就一直
    保持指针可见，停止 1.2 秒后才隐藏；
  · **停止滚动后自动归位**：滚轮停止 1.5 秒就回到正在播放的那一句，不再
    只在"鼠标移出窗口"时才归位。播放器自身只在"换句且仍在渲染范围内"才
    自动对齐，滚远会卡住，所以这里直接调它的公开 `resetScroll()`。

  · O3 全屏必须串行、必须确认结果、失败要回滚标题栏

  · P10 滚轮必须算作指针活动
