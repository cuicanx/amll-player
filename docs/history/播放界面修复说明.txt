播放界面七项修复说明
================================================

1. 全屏菜单项状态不同步
------------------------------------------------
根因：`AMLLContextMenuContent` 是随应用挂载一次的组件——每次右键只是新建
一个 Radix portal，组件本身不重新挂载。我上一轮在它里面用
`useEffect(() => isFullscreen().then(setState), [])` 查询窗口状态，拿到的是
**应用启动那一瞬间**的值，之后永远不变，所以窗口已经全屏，菜单还写「进入
全屏」。

修法：
  · 新增 `borderlessFullscreenAtom`，作为全屏状态的唯一来源；
  · `enter/exit/toggle` 每次切换后同步写入；
  · 菜单改为读这个 atom（实时）；
  · 菜单每次打开时（`ContextMenu.Root` 的 `onOpenChange`）再向原生窗口
    校正一次，防止有外部路径改变过状态。

2. 「进入全屏」的定义
------------------------------------------------
之前我的表述把它叫「窗口化全屏」，这是理解错误。这里统一为**无边框全屏**：

  · 抬升原生 fullscreen 标志（系统把窗口铺满整个显示器，含任务栏，且没有边框）；
  · 同时隐藏自绘标题栏（主窗口本身是 `decorations: false`）。

**明确不是「最大化窗口」**：最大化的窗口仍然保留工作区预留，底部会留一条
任务栏高度的空白——这正是早先黑边的来源。

现在只有一条实现路径：
  F11 ─┐
  右键菜单 ─┼→ toggleBorderlessFullscreen → enter/exitBorderlessFullscreen
（设置里关闭该功能时也会走 exit 退出）除 `utils/borderless-fullscreen.ts`
外，任何文件都不再出现 `setFullscreen(` —— 已加断言守住这一点。

3. 「显示歌词」勾选符号错位
------------------------------------------------
根因是我上一轮统一菜单节奏时，把 `padding: 6px 9px !important` 与 `gap`
一起套到了 `menuitemcheckbox` 上。可勾选行的勾选符号是 Radix 自己布局的
独立槽位（父级预留了左内边距），被强制改成 9px 后，符号就压到文字上了。

修法：可勾选行（`menuitemcheckbox` / `menuitemradio`）不再覆盖 padding 与
gap，只统一字号、行高、圆角、最小行高；普通菜单项保持原有内边距。

4. 其他贡献者卡片过小
------------------------------------------------
上一轮为了「弱化」把贡献者改成了小号 chip。本轮按要求恢复原尺寸：
`Card` + `Avatar size 2` + 加粗昵称，网格 `minmax(20rem, 1fr)`。
位置仍是「其他贡献者」小标题之下，主维护者卡片保持高亮——层级不变，
只是尺寸回来了。

5. 设置页左上角按钮被轻微遮挡
------------------------------------------------
两个叠加原因：
  · 按钮行原本 `top: 0`，40px 的按钮正好贴着窗口左上角，被窗口圆角切到；
  · 系统标题栏（`#system-titlebar`，z-index 10000，整宽拖拽区）盖在按钮
    行（z-index 10）之上，按钮顶部 32px 落在拖拽区里，视觉上没事但点不到。

修法：按钮行 `top: 10`、`z-index: 10001`（高于标题栏），整个设置内容区
同步下移 10px（`calc(var(--space-8) + 10px)`），按钮行与侧栏首项的间距
保持 8px 不变。

6. 悬停歌词持续滚轮 → 突然变模糊、滚不动
------------------------------------------------
根因不是歌词播放器，是**光标自动隐藏**的实现：它盖了一张
`position: absolute; inset: 0; cursor: none; z-index: 9999` 的透明层。
鼠标静置 1.2 秒（滚轮不算 mousemove）后这层出现，之后：

  · 滚轮事件全部落到这层，歌词播放器的 `wheel` 监听收不到 → 滚不动；
  · 播放器收不到 `pointerleave`（指针已经被遮罩接管）；
  · 播放器在滚轮停止 150ms 后判定「交互结束」，500ms 后允许自动对齐，
    于是下一次换句时突然弹回当前句；远行中的歌词经过模糊区间，
    看起来就是「突然变模糊，然后又恢复」。

修法：删掉这个遮罩，改为在页面容器上加 `cursor: none` 的类
（`.cursorHidden, .cursorHidden *`），不再有任何元素插在指针与歌词之间。

7. 鼠标离开后不回到当前播放句
------------------------------------------------
我读了实际使用的 core 0.6.0 源码确认：播放器的自动归位只在
「当前句发生变化 && 该句仍在渲染范围内」时触发。滚得远一些，当前句被
移出渲染范围，就永久卡住——这是库的既有行为，不是我们的回归。

但库本身提供了公开方法 `resetScroll()`，注释写明用途正是「用户滚动完毕、
但歌词未自动归位时立刻归位」。

修法：`pointerleave` 后 700ms 调用它（`pointerenter` 则取消），仅播放中
生效（暂停时用户多半是在看某一段，不应抢走视线）。
获取实例的方式：`PrebuiltLyricPlayer` 不透传 ref，所以从 DOM 节点的
React fiber 向上查找，并用 `resetScroll` + `getLyricLines` 做鸭子类型
校验，确保只会命中真正的播放器实例；找不到就静默跳过，不影响任何现有行为。
