AMLL Player 界面与更新系统优化（0.0.1149）
================================================

一、音频解码信息弹窗（图 1）
------------------------------------------------
问题：原来是裸 Radix DataList 直接塞进默认对话框——
  · 「音频通道数量」这一行忘了包 DataList.Label，标签列整个丢掉，
    所以整张表左边不齐；
  · 行距不均、字号没有层级、表头/正文混在一起；
  · RTL 一样的默认蓝色大按钮，和全站 soft 风格不统一。

改法：
  · 改成「标题 + 副标题 / 数值区 / 底部按钮」三段式，标题 15px 600，
    副标题 12px 55% 透明度；
  · 标签-数值改为两列 grid（标签灰、数值 500 字重 + 等宽数字），
    行间用 1px 细线分隔，数值右对齐、超出省略；
  · 右上角加圆形关闭按钮，底部关闭按钮改为 soft / size 2；
  · 采样率加千分位与 Hz 单位后缀，通道加「声道」单位，编解码器与
    采样格式统一大小写；
  · 容器换成更实的对话框材质（--amll-glass-dialog）+ 18px 圆角 +
    分层阴影，与全站毛玻璃一致但明显高于菜单一层。

二、右键菜单（图 2）
------------------------------------------------
  · 未开启「F11 无边框全屏」时，不再显示全屏项（该功能对用户无效，
    只是噪音）；开启后标题随当前状态显示「进入全屏 / 退出全屏」；
  · 全屏项复用 borderless-fullscreen.ts 的同一实现，不再自带一份
    setFullscreen 逻辑；
  · 菜单节奏统一：内边距 6px、行高 30px、圆角 7px、分隔线用发丝色，
    快捷键字（Ctrl Alt ←）降为 11.5px / 55% 透明度，与三点菜单一致。

三、F11 全屏过渡
------------------------------------------------
「黑一下」的根因：上一版为了盖住原生的硬切换，铺了一层全黑遮罩，
切换前后各做 140ms 的淡入淡出——那层黑就是用户看到的黑屏。
本次直接删除遮罩。

「先变小再变大」的根因：进入全屏时要先取消最大化（否则底部留任务栏
高的黑边），旧代码在 unmaximize 之后 await 了两帧才 setFullscreen，
Windows 趁机画出一帧「还原后的小窗口」；退出时同理，setFullscreen(false)
与 maximize 之间也有一次 await。
本次把两次调用合并进同一个 Promise.all，一次 IPC 往返内完成，不再有
中间帧。退出后还会等 resize 落定再恢复标题栏外观，避免最大化图标与
32px 偏移在窗口移动过程中闪入。

说明：Windows 没有原生的全屏切换动画，能做到的是「瞬时且无中间态」，
这比任何遮罩都更接近系统级观感。

四、全屏后左上角返回箭头
------------------------------------------------
真正的根因不是 tooltip，而是布局塌陷：
  全屏时 #system-titlebar 用 display:none → ResizeObserver 量到 0px →
  写入 --system-titlebar-height: 0px → 设置页那行 40px 按钮在「0 高度 +
  align-items:center」的容器里上下各溢出 20px，顶部被窗口边缘裁掉一半。
改法：
  · 全屏时标题栏改为 visibility:hidden + pointer-events:none，仍然占
    32px，量高不再归零，窗口化/全屏之间也不再跳 32px；
  · 按钮行固定 40px 高、贴顶定位，不再依赖标题栏变量；
  · 返回按钮的 Tooltip 整个移除（悬停那个白框就是它，还会挡住箭头），
    保留 aria-label 供读屏使用。

五、任务栏歌词的「弹一下就没」
------------------------------------------------
根因：窗口以 decorations(true) + skip_taskbar(false) 创建，会先作为一个
带标题栏的普通窗口出现在屏幕默认位置，随后才被 embed 进任务栏；同时
任务栏也短暂多出一个按钮（所以「底部任务栏也有同样现象」）。
改法：
  · decorations(false)、skip_taskbar(true)、shadow(false)、focused(false)；
  · 创建即隐藏，embed 与首次定位完成后再由 Rust 端延迟 180ms show；
    页面不再自行 show（以前页面首帧就 show，比 embed 更早）；
  · 保留 1.5s 兜底，保证任何情况下不会永远不出现。

六、任务栏歌词长句方向
------------------------------------------------
右对齐时内容贴右，一行的尾部本来就在最右边，于是播放时先看到句尾、
再往回滚——读起来是反的。
改为：右对齐时从 +maxTranslate 起步（首字对齐左缘）向 0 运动，文本
左移、后文从右缘进入，即正常的从左往右阅读；measure 阶段就把初始
位移写好，避免第一帧跳一下。

七、更新日志排版
------------------------------------------------
  · 新增 ReleaseNotes 组件：解析 markdown（#/##/### 标题、- 与 1. 列表、
    > 引用、--- 分割线、**粗体**、`行内代码`、[链接](url)）；同时把
    「短、无句末标点」的独立行识别为分组标题，兼容纯文本手写日志；
  · 层级：卡片容器 + 版本号 chip（旧 → 新）+ 分组标题 12.5px/600 +
    条目 12.5px/1.65 + 引用块左侧 2px 竖线 + 超长可滚动；
  · CI 的 releaseBody 改为结构化 markdown（## 更新内容 / ### 本次变更 /
    --- / ## What's new），不再把整段提交信息当正文。

八、关于页致谢层级
------------------------------------------------
三级：应用标识（名称 + 版本·提交·分支 + 一句话定位）
   → 高亮维护者卡片（头像 + cuicanx + 「主要维护者」chip + 说明 +
     GitHub / 仓库链接，带淡蓝渐变底）
   → 弱化区：上游 AMLL 致谢（11.5px / 50%）+ 其他贡献者（小号 chip 行，
     16px 头像 + 昵称，72% 透明度）。
其他人不再是和本人同等大小的卡片。

九、更新提示跳转
------------------------------------------------
主界面「有可用更新」徽标原来跳 /settings#updater，但设置页的活动页是
本地状态，hash 从来没被读取，所以总是落在「常规」。
改为跳 /settings#about，并让设置页监听 hash（含 hashchange），支持
#about / #player.about / #extension.xxx 三种写法。

十、更新系统：地区化 + 提速
------------------------------------------------
1) 地区判定（utils/update-region.ts）
   并发请求 4 个 geo 接口（cloudflare trace / ipapi / ip.sb / ipip），
   谁先答就用谁，单次 2.6s 超时，胜者取消其余请求；结果按「cn/global」
   缓存 6 小时；全部失败回退 cn（镜像对境内外都能用，只是境外不必绕）。

2) 更新检查与下载移到 Rust（src-tauri/src/updater.rs）
   原因：Tauri 更新插件只在启动时读一次 tauri.conf.json 的 endpoints，
   前端无法按地区改顺序；而清单里的下载地址是 CI 生成的。
   现在用 updater_builder().endpoints(...) 在运行时传入排序后的清单：
     境外：官方 latest.json → 镜像清单 → 镜像官方清单
     境内：镜像 latest-mirror.json → 镜像官方清单 → 官方 latest.json
   下载地址随清单变化：境外直连官方源（不走第三方代理），境内走
   gh-proxy 直链（不经 api.github.com 与 release-assets 域名）。

3) 速度可见
   Rust 每收到一块数据就 emit updater://progress，前端换算为
   「xx% · 1.8 MB/s」（0.7/0.3 指数平滑，避免数字乱跳）。

4) 失败重试
   点击重试会强制重新探测地区，网络从 VPN 切回直连后不会继续走错源。
   失败文案仍按清单失败/签名失败/超时/连接失败分类给出可执行提示。

5) 贡献者与头像
   同一套地区判定：列表按地区先请求对应源，1.2s 后并发另一源兜底；
   头像 avatars.githubusercontent.com 在境内走镜像，避免一片裂图。

关于你给的那个链接
------------------------------------------------
https://productionresultssa3.blob.core.windows.net/actions-results/...
这是 GitHub Actions 的「运行产物」临时地址：带 se/sig（签名 + 过期时间），
绑定某一次具体 run，几小时后失效，且只对该次构建有效。它能下载，但
不能作为更新源——版本号与签名清单都不在这里，克隆到别的机器会立刻失效。
因此没有把它接进更新链路；真正的加速靠上面的镜像清单 + 地区选源。
