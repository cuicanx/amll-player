【一、这个版本解决了什么】

症状：音乐文件已内嵌歌词，但播放时不显示；必须进入「歌曲 ->
元数据 -> 重新从文件中读取元数据」逐首手动操作才出现。

根因（三条，编号对应下方修复项）：
 1. 主因 - 两条数据入口实现不一致。
    通过「扫描文件夹 / 文件夹歌单刷新」入库时走
    packages/player/src-tauri/src/db/scanner.rs::process_file，
    该函数只用 find_lyric_file() 查同名外挂歌词文件，把已经打开的
    AudioReader.metadata() 里的内嵌歌词整个丢弃，写进 songs 表的
    lyric / lyric_format 都是空串。播放时 LocalMusicContext 的
    LyricContext 从 db.songs.get(musicId) 读到空串，
    useLyricParser 返回 hasLyrics=false，进而 setHideLyricView(true)。
    而设置页那条路径调用 read_local_music_metadata -> build_audio_info
    -> get_meta("lyrics")，能拿到内嵌歌词并写回数据库，于是"手动重读
    就好了"。这正是症状的直接来源。
 2. 次因 - 元数据键名覆盖不全。ffmpeg_audio 0.2.0 的 extract_dict
    原样保留 FFmpeg 的 AVDictionary 键名、不做归一化：ID3v2 常见
    lyrics / USLT / USLT:eng / TXXX:LYRICS，FLAC/OGG 常见大写
    LYRICS / UNSYNCED LYRICS，MP4 常见 ©lyr。原代码只认小写字面量
    "lyrics"；scanner 里连 title/artist/album 都用了大小写敏感的
    metadata.get("title")。
 3. 次因 - 歌词格式被硬编码为 "lrc"。内嵌 TTML / QRC / YRC / ESLRC /
    LYS 时被强行交给 parseLrc()，解析出 0 行，等同于不显示。

修复：
 [F1] 新增零依赖共享模块 packages/player-core/src/lyric_meta.rs：
      键名归一化（大小写/分隔符/语言后缀）、大小写不敏感取值、
      内嵌歌词候选优先级排序（并显式排除 LYRICIST 等"作词者"字段）、
      内容格式嗅探 resolve_lyric() 统一"外挂文件优先 / 内嵌兜底"。
 [F2] scanner.rs 改用 resolve_lyric() 与 get_meta_ci()；
      utils.rs::build_audio_info 改用同一套共享逻辑；
      music_info.rs 用 detect_lyric_format() 取代硬编码 "lrc"。
      => 新导入 / 重新扫描的歌曲入库即带歌词。
 [F3] 播放时懒加载自愈：LocalMusicContext 在检测到 songs.lyric 为空
      且是本地文件时，自动调用 readLocalMusicMetadata 回填数据库。
      update_song 发出 db-row-changed -> useDbQuery 重新查询 ->
      useLyricParser 渲染，同一次播放内即显示。
      每首歌每次会话只尝试一次；无内嵌歌词时不写脏数据。
      => 已经导入过的历史歌曲无需任何手动操作。
 [F4] 设置页"重新从文件中读取元数据"不再硬写 "lrc"，改用嗅探结果。

【三、分场景使用步骤】

场景 1：只想验证改动是对的（不需要编译整个 App）
  1) 双击「验证全部.cmd」
  2) 看到 "总计: 7/7 组检查通过" 且末尾无 FAIL 即通过。

场景 2：把修复应用到自己的 amll-player 仓库
  1) cd <你的 amll-player 仓库根目录>
  2) patch -p1 < <工作区>/v1-bugfix.patch
     （Windows 无 patch 时，直接把 v1-bugfix/packages 覆盖过去，
       或用 git apply -p1 v1-bugfix.patch）
  3) 按「改动文件清单」核对 12 个文件。

场景 3：构建并实际播放（需要 Rust + pnpm 完整开发环境）
  1) 本机需 Rust stable、pnpm 11.7.0、Tauri 2 的系统依赖、
     以及 FFmpeg 开发库（ffmpeg_audio_sys 构建需要）。
  2) cd v1-bugfix && pnpm install
  3) cd packages/player && pnpm tauri dev
  4) 导入一首带内嵌歌词的本地音乐（FLAC/MP3/M4A 均可），直接播放。

场景 4：老用户（库里已有大量无歌词记录）
  不需要做任何事。修复后首次播放每首歌时会自动回填，
  之后写入数据库，第二次起无任何额外开销。

【六、版本二（LX Music 联动）预研备注】

 已确认上游背景：amll-player 是作者把原 BetterNCM 插件里的
 Apple-Music-like Lyrics 歌词组件拆出来的独立 Tauri 程序；相关仓库
 applemusic-like-lyrics（React/Vue 组件本体）、ws-protocol（WS 协议库）、
 AMLL-WS-Connector（BetterNCM 插件实现）、amll-player-plugin-template
 均属同一组织 amll-dev。仓库内已有 WSProtocolMusicContext /
 server.rs 的 WS 协议实现，是天然的联动衔接点。
 内嵌可行性、音源接管与播放状态同步机制将在版本二展开。
